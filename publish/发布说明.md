# 发布到 AstroBox 资源社区：现状与操作

> 目标：让「点记」出现在 AstroBox 的「资源社区」里，带圆形 Logo 和应用名，而不是本地选文件时只显示文件名 + RPK 图标。

## 一、为什么必须走社区源

AstroBox 2.x 前端不解析 rpk 里的 manifest：本地选文件的队列条目，名字取**文件名**、图标取**按扩展名的文件图标**（源码里是 `basename` + `file-icon-rpk`）。只有「社区源（provider）」条目的名称和图标来自服务端元数据。所以想要 Logo + 应用名，必须把资源提交进官方源索引 `AstroBox-Repo/index_v2.csv`。

## 二、当前仓库已具备的发布形态（v2 布局）

AstroBox-Repo 的校验脚本 `.github/scripts/resource_submissions.py` 会检查目标仓库在指定 commit 上存在 `manifest_v2.json`，并且 `manifest.downloads` 里每个 `file_name` 都真实存在于该 commit。仓库现在的结构就是按这个来的：

```
manifest_v2.json                                       条目元数据（v2）
media/icon.png      192x192                            图标
media/cover.png     1200x800  (3:2)                    头图
media/preview-1.png 1200x800                           预览图 1
media/preview-2.png 384x980                            预览图 2（手环界面 192x490 的 2x）
downloads/com.taptally.scoreboard.release.1.0.0.rpk    分发包
```

`manifest_v2.json` 关键字段：

```json
{
  "item": { "id": "com.taptally.scoreboard", "restype": "quick_app", "name": "点记",
            "description": "...", "preview": ["media/preview-1.png", "media/preview-2.png"],
            "icon": "media/icon.png", "cover": "media/cover.png",
            "author": [{ "name": "DVLZY", "author_url": "https://github.com/DVLZY" }] },
  "links": [],
  "downloads": { "xmb9": { "version": "1.0.0",
                           "file_name": "downloads/com.taptally.scoreboard.release.1.0.0.rpk",
                           "versionCode": 1, "updatelogs": [{ "version": "1.0.0", "content": "..." }] } },
  "ext": {}
}
```

- 设备代号只写 `xmb9`：`devices_v2.json` 里小米手环 9 与 9 NFC（M2345B1 / M2346B1）都是 `xmb9`；`n66` 是旧代号，v2 设备表里没有，写进去会被判「设备代号不存在」。
- 图标 192×192、头图 3:2 1200×800，符合《资源提交规范》的推荐值。

## 三、投稿流程（PR 只允许改 `tmp/**`）

AstroBox-Repo 的工作流 `resource-submissions.yml` 监听 `pull_request` 的 `tmp/**` 路径，校验脚本会**拒绝**任何非 `tmp/` 的改动。每个 PR 只能含一个提交目录，目录里两个文件：

```
tmp/<任意1>/<任意2>/resource.csv   ← 与 index_v2.csv 同表头、恰好 1 行数据
tmp/<任意1>/<任意2>/request.json   ← {"schema_version": 1, "mode": "create"}
```

`resource.csv` 内容（与 `publish/index_row.csv` 同源，由 `publish/make_submission.py` 生成）：

```
id,name,restype,repo_owner,repo_name,repo_commit_hash,icon,cover,tags,device_vendors,devices,paid_type
com.taptally.scoreboard,点记,quick_app,DVLZY,taptally-miband,<commit>,media/icon.png,media/cover.png,实用工具;计分;比分;台球;乒乓;羽毛球;棋牌;对局,xiaomi,xmb9,
```

生成提交物：

```bash
python publish/make_submission.py --out <临时仓库目录> --commit <发布commit短哈希>
```

然后把该目录推到一个 **fork 的 AstroBox-Repo**，开 PR 指向 `AstralSightStudios/AstroBox-Repo:main`。CI 通过后由维护者合并，`apply-pending` 会自动把行写进 `index_v2.csv`。

> 被关闭后想重开：在 PR 里评论 `[ABCC_REOPEN]`。（审核员拒绝会打 `[ABCC_REFUSE]` 标签。）

## 四、提交前自检清单

- [ ] `manifest_v2.json` 的 `item.name` 与 CSV 的 `name` **完全一致**（都是「点记」）
- [ ] `downloads` 里的 `file_name` 在目标 commit 上真实存在
- [ ] `devices` 列用分号分隔、无逗号无引号，代号在 `devices_v2.json` 里存在（`xmb9`）
- [ ] `media/icon.png`、`media/cover.png` 能通过 raw 链接访问（公开仓库即可）
- [ ] CSV 恰好 1 行数据，无零宽字符、无 U+FFFD
- [ ] 版本号与 rpk 内 `versionCode` 对应（当前 1.0.0 / 1）

## 五、待办

1. **先修 R7**（比分持久化）再上架：现在分发的 1.0.0 是带诊断横条的构建，R7 未确认修好，不适合作为社区首版。
2. 修好后重打包 → 更新 `downloads/*.rpk` 与 `manifest_v2.json` 的 version/versionCode → 重新取 commit → 重跑 `make_submission.py`。
3. 提 PR；合并后 AstroBox「资源社区」刷新即可看到「点记」的 Logo 与名称。
