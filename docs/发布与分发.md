# 发布与分发

> 主渠道是 **GitHub Release**（存 rpk 附件 + 版本说明）；安装走 AstroBox。
> AstroBox 资源社区（`AstroBox-Repo`）这条路**已关闭**，历史与原因见第五节。

## 一、发版步骤

```bash
# 1) 改版本号：src/manifest.json 的 versionName / versionCode（必须递增）
#    同步 src/common/store.js 里的 APP_VERSION（列表页页脚显示它）

# 2) 语法自检（aiot-toolkit 遇到语法错误不报错，会静默编成空模块）
python scripts/check_syntax.py

# 3) 打正式包（自签证书，见 scripts/gen_sign.sh）
node node_modules/aiot-toolkit/lib/bin.js release --enable-jsc --drop-console true

# 4) 复制一份给用户/AstroBox 用的文件名（队列里显示的就是文件名，用中文即可）
cp dist/com.taptally.scoreboard.release.<版本>.rpk dist/点记-<版本>.rpk
```

然后同步这几处，缺一处就会出现「包对文档不对」：

| 位置 | 改什么 |
| --- | --- |
| `downloads/` | 放入新 rpk，删掉旧的（仓库只留当前版本） |
| `manifest_v2.json` | `downloads.xmb9` 的 `version` / `file_name` / `versionCode`，并往 `updatelogs` 头部插一条 |
| `docs/CHANGELOG.md` | 新增版本段：改了什么、为什么改、有什么代价 |
| `docs/验证清单.md` | 新功能对应的验收项、版本号 |
| `README.md` | 版本号、功能表、界面说明 |
| `publish/gen_*.py` | 素材脚本里的常量（圆角、中缝、字号系数）要跟源码一致，否则出的图和 App 不一致 |

## 二、发 GitHub Release

一键脚本（推荐）：

```bash
python scripts/publish_release.py                 # push + 建 Release + 传附件
python scripts/publish_release.py --retry 18 --interval 40   # 网络不稳时自动重试
python scripts/publish_release.py --dry-run       # 只检查版本号/附件/待推送提交数
```

Release 正文取自 `docs/release-notes-<版本>.md`，附件取自 `dist/TapTally-<版本>.rpk`
（脚本会自动从 `com.taptally.scoreboard.release.<版本>.rpk` 复制出 ASCII 文件名）。

手动做的话，没有 `gh` CLI，用 API + GCM 凭据：

```bash
# 取 token（GCM 里已存，静默读出）
printf 'protocol=https\nhost=github.com\n\n' | git credential fill | sed -n 's/^password=//p' > "$TEMP/_ghtok"

# 建 Release：POST /repos/DVLZY/taptally-miband/releases
# 传附件：  POST <upload_url>?name=TapTally-<版本>.rpk  （body 是 rpk 原始字节）
```

两个坑：

- **附件名必须 ASCII**。传 `点记-1.8.1.rpk` 会被截成 `-1.8.1.rpk`，改用 `TapTally-1.8.1.rpk`。
- Release 正文里的图片用 `raw.githubusercontent.com` 绝对地址，别用相对路径。

## 三、签名

```bash
bash scripts/gen_sign.sh      # 生成 sign/private.pem + sign/certificate.pem（RSA-2048 自签）
```

- `sign/` 已在 `.gitignore`，**不要提交私钥**
- 证书丢了就没法再给已装用户做覆盖安装（签名不匹配会被拒），请自己备份
- `release` 走 PRODUCTION 分支的签名路径：只认 `sign/release/` 或 `sign/` 下的证书；
  找不到会直接报 `The current mode is production, and there is a problem with the certification path`
- 早期版本用工具链内置调试证书签名（`build` 模式），1.7.0 起换成自签证书 ⇒ 跨这道线的升级必须先卸载

### 附：递交协议（留档）

- PR **只允许改 `tmp/**`**，且只允许 `resource.csv` 与 `request.json` 两个文件
- 路径要 `tmp/<任意>/<任意>/`（脚本要求至少 4 段），一个 PR 只能有一个提交目录
- `resource.csv`：表头与 `index_v2.csv` 一致（12 列），**恰好 1 行数据**，`devices` 用分号分隔且代号必须存在于 `devices_v2.json`
- `request.json`：新建是 `{"schema_version":1,"mode":"create"}`；改版还要带 `original_id` / `base_entry_digest` / `base_catalog_commit`
- 目标仓库必须有 `manifest_v2.json`，且 `downloads[*].file_name` 指向的文件真实存在于提交的 commit 里
- 被关闭后可评论 `[ABCC_REOPEN]` 重开；审核员拒绝会打 `[ABCC_REFUSE]`
