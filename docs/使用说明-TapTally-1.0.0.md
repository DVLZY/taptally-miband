# 点记 TapTally · v1.0.0 使用说明

> 适用设备：小米手环 9 NFC（Xiaomi HyperOS / Vela 快应用）
> 本版本为 **诊断版**：功能与正式版一致，但中间黑条会显示存储读写状态，用于定位"退出重进分数归零"的问题。

## 二、安装（首次 + 本次升级）

1. 手机/电脑打开 **AstroBox**，连接手环（MAC `04:34:C3:0B:A6:74`，BLE 连接）。
2. 设备 → 安装队列 → 选择 `com.taptally.scoreboard.debug.1.0.0.rpk`（或改好名的 `TapTally-1.0.0.rpk`）。
3. 等待安装完成（手环上会出现"点记"图标）。
4. 旧版（`com.sports.scoreboard`）请先在 AstroBox「第三方应用管理」里卸载，再装本包；同包名以后升级才用覆盖安装（versionCode 递增）。

> 注意：必须用 `build --enable-jsc` 的产物，手写 zip 或未经 jsc 编译的包会导致手环重启。

## 三、界面

```
┌─────────────────────────┐
│                         │
│         浅绿 #a8e6cf     │  ← 上半区（上方选手）
│           0             │     数字深绿 #0b6b4f
│                         │
├─────────────────────────┤
│   R:0-0 W:ok   重置      │  ← 中间黑条（4% 高，诊断信息）
├─────────────────────────┤
│                         │
│         浅蓝 #b3e5fc     │  ← 下半区（下方选手）
│           0             │     数字深蓝 #0b4f6b
│                         │
└─────────────────────────┘
```

- 上下各占 **48%**，中间黑条 **4%**。
- 数字字号固定 `300px`（设计宽 480），**3 位数可能溢出**，属待优化项（R8）。
- 进入应用自动**常亮屏幕**，退出时自动解除。

## 四、操作

| 操作 | 位置 | 效果 | 震动反馈 |
| --- | --- | --- | --- |
| **单击** | 上半区 / 下半区 | 该方 **+1** | 短震 1 次 |
| **双击**（同侧 300ms 内两击） | 上半区 / 下半区 | 该方 **-1**（最低到 0，0 分时不再减） | 短震 2 次（间隔 130ms） |
| **长按** | 上半区 / 下半区 | 该方 **-1**（备用减分方式） | 短震 2 次 |
| **上滑** | 屏幕任意处 | 第一次：横条显示 `再滑确认`，短震 1 次<br>2.5 秒内**再上滑一次** → 比分归零 `0:0` | 归零时短震 2 次 |
| **右滑** | 屏幕任意处 | 退出应用（回到表盘） | 无 |

判定细节：
- 上滑：纵向位移 < -90 且横向位移绝对值 < 90。
- 右滑：横向位移 > 90 且纵向位移绝对值 < 90。
- 单击有 **300ms 判定延迟**：点一下后约 0.3 秒才 +1（这是为了区分双击，属既定设计，可改）。
- 分数上限 199，超过不再增加。
- 比分实时写入本地存储，key = `taptally_v1`，值格式 `"上-下"`（如 `"3-2"`）。

## 五、诊断文字说明（本版重点）

每次变化后中间黑条会刷新，格式为 `R:xxx` 或 `R:xxx W:yyy`。

### `R:` 部分 —— 打开应用时读取存储的结果

| 显示 | 含义 |
| --- | --- |
| `R:null` | 读到**空值**（没有存过 / key 不对 / 读取失败静默返回空） |
| `R:0-0`、`R:3-2` | 读到了上次的比分，格式为 `上-下` |
| `R:fail<数字>` | `storage.get` 的 fail 回调触发，数字是错误码 |
| `R:throw` | 调用 `storage.get` 直接抛异常 |
| `R:` 后跟很长一坨 | 回调返回的是对象被整体转成了字符串（说明解析形态需再调整） |

### `W:` 部分 —— 每次加/减分后写存储的结果

| 显示 | 含义 |
| --- | --- |
| `W:ok` | 写入成功 |
| `W:fail<数字>` | 写入被拒，数字是错误码 |
| `W:throw` | 调用 `storage.set` 抛异常 |
| （无 W 部分） | 还没触发过写入 |

## 六、测试步骤（请按顺序做，并把结果告诉我）

1. **打开「点记」** → 记下横条文字（例如 `R:null`）。
2. **点上半区 2 下**（等每次 +1 落定，别连太快）→ 比分应为 2，横条应变成 `R:... W:ok`。
3. **点下半区 1 下** → 比分 2:1。
4. **右滑退出** → 回到表盘。
5. **重新打开「点记」** → 记下横条文字；**观察上下数字是否恢复成 2 和 1**。
6. **验证 R4**：点中间黑条，确认**没有任何反应**（不会重置）。
7. **验证重置**：上滑一次（横条变 `再滑确认`）→ 再上滑一次 → 应归零。
8. **验证常亮**：进应用后放下手环不动 15 秒，看屏幕是否熄灭。

### 请回报这三行
- ① 首次打开时横条：`______`
- ② 点两下后横条：`______`
- ③ 右滑退出重进后横条与数字：`______`

### 结果判读（我自己用这个判断根因）
- ③ 显示 `R:2-1` 且数字恢复 → **已修好**，去掉诊断文字出正式版。
- ③ 显示 `R:null`（或空）而②曾有 `W:ok` → **写入成功读取失败**，改用 `@system.file` 方案。
- ② 出现 `W:fail<码>` → **写入被拒**，按错误码换存储接口。
