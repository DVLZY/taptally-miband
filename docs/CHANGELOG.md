# 更新记录

## 1.0.1（versionCode 2）

- **修复：比分不保存**（R7）。原先只写 `@system.storage`，重启后读不到。现在：
  - 写入走**双通道**：`storage.set` + `@system.file`（`internal://files/taptally-score.txt`）；
  - 读取时两处都读，任一处能解析出合法比分就恢复；
  - 恢复完成后「锁定」，不再被框架初始值或异步回写覆盖；用户一旦操作过，就不再有任何回写；
  - 右滑退出、切后台（`onHide`）、页面销毁（`onDestroy`）时都会**补写一次**。
- **新增：字号自适应**（R8）。比分到 3 位数（100+）时字号从 300px 降到 200px，避免在设计宽 480 上溢出。
- **变更：中间横条不再响应点击**（R4）。横条只作分隔与「再滑确认」提示，不再有重置入口；重置仍走上滑二次确认。
- 中间横条平时不再显示任何文字（上一版是诊断文字）。

## 1.0.0（versionCode 1）

- 首个可用版本：上下双色分区、单击 +1 / 双击 −1 / 长按 −1、上滑二次确认归零、右滑退出、屏幕常亮、比分持久化。

## 1.2.0（versionCode 5）

- 新增设备自适应：运行时读取 `@system.device.getInfo()` 的 `screenWidth/screenHeight/screenShape`，
  反推设计高度，动态计算卡片内边距、圆角、字号与列表条目尺寸（手环 192×490、9 Pro 336×480、圆表 466×466 均适用）
- 圆屏（`screenShape === 'circle'`）改用胶囊形卡片 + 70 设计 px 缩进，避免四角被圆形边框裁切
- 记分数字字号不再写死，按卡片宽高与位数共同约束（1/2/3 位自动收缩）
- 列表页同样自适应：条目高度、色条、序号、比分、时间宽度全部由条目高度推导
- 中间横条支持**长按显示屏幕参数**（`宽x高 形状`），用于未适配机型上确认分辨率
- manifest 增加 feature `system.device`

## 1.3.0（versionCode 6）

- 记分列表改为**时间降序**（`ts` 倒序渲染，最新一局在最上方），不再依赖写入顺序
- 列表条目只保留**序号 + 比分**，去掉时间列；行高从 7.8% 提升到 9.2%（60–132 设计 px），比分字号同步放大到条目高的 54%
- 条目宽度、序号列宽、左侧色条全部按条目高推导，圆屏仍左右缩进 70 设计 px

## 1.3.1（versionCode 7）

- 图标改为**斜向分隔**：圆内分隔线倾斜 28°（左下→右上），`0` 居左上、`9` 居右下；
  数字位置与倾角同源推导，任意尺寸都各自居中于半区
- 同步更新 `media/icon.png`(192) / 封面头图 / 预览图 1、2，封面文案补上「下滑看记分列表」

## 1.3.2（versionCode 8）

修复用户真机反馈的 4 个问题：

1. **列表页标题居中**：`.head` 改为 `justify-content: center`，删除右侧 `n / 10` 计数（`count` 字段整体移除）
2. **列表条目字号放大 + 色条移位**：行高系数 0.092 → 0.104；比分 0.54 → 0.66 倍行高；序号 0.26 → 0.40 倍行高；
   行内顺序改为 **序号 → 色条 → 比分**（新增 `accentMr`）
3. **单击历史记录不还原比分**：`index.ux` 不再依赖页面间共享的 refreshFlag，
   改为 `onHide` 置 `wasHidden`、`onShow` 时 `restore(true)` **强制回读磁盘**；`store.loadScore/loadRecords` 增加 `force` 参数
4. **历史只留 1 条**：数据层重写为 **内存缓存 + 纯文本落盘**（`t-b-ts;…`，不再用 JSON），
   写入先更新缓存再落盘；`force` 回读时若磁盘为空则保留缓存，不会把列表清空；`MAX_RECORDS` 10 → **5**

新增 `docs/验证清单.md`（27 项逐条验收表）。

## 1.3.3（versionCode 9）

真机反馈「重装后手环上 logo 没变、历史仍只有 1 条」，本版先加**可观测手段**，再据读数定位：

- 图标改为 **128×128**（与官方模板同尺寸，排除大图不被列表页接受的可能）；包内 `common/logo.png` 已校验与新图完全一致
- 记分页**长按中间窄缝**显示：`屏幕宽x高 形状 v版本号 r记录条数`（例：`192x490 rect v1.3.3 r3`）
- 每次上滑归零后，窄缝短暂显示「已存 N 条」1.5 秒
- 列表页**长按标题「记录」**：页脚切换为诊断串 `S<存储字符数> F<文件字符数> N<内存条数>`，`null` 表示该通道读不到
- 列表页页脚常驻 `v1.3.3 · 单击恢复 / 长按删除`，一眼确认跑的是哪一版
- `store.js` 导出 `APP_VERSION` 与 `debugStats(cb)`

## 1.3.4（versionCode 10）

- 修复进入应用瞬间「卡片先直角、后圆角」的闪烁：`border-radius` 原本只靠数据绑定下发，
  首帧还没生效；现在在 `.card` / `.item` 上先写死与手环9 一致的默认圆角（52px / 30px），
  绑定值到达后再按屏幕形状覆盖（圆屏仍会切成胶囊形）

## 1.3.5（versionCode 11）

- 修复「半区长按：先 −1 又 +1」：系统在 longpress 之后仍会派发一次 click，
  而单击是延迟 300ms 才落分的，于是长按的 −1 之后又被补了一次 +1。
  现在长按处理里先取消挂起的单击定时器并打上 `longMark`，`tap()` 见到标记直接丢弃该次点击；
  列表页同样加了保护（长按删除后不会再触发单击恢复）
