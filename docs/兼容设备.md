# 兼容设备（点记 / TapTally 1.8.1）

> 结论先行：应用按**屏幕宽高比自适应**，理论上覆盖所有支持快应用的小米穿戴设备；
> 但**只有小米手环 9 / 9 NFC 做过真机验证**，其余机型的数值是按下文公式推算的，需要使用后确认。

## 一、自适应原理

快应用用 `designWidth: 480` 做设计稿映射，CSS px 按屏幕宽度等比缩放。运行时读
`@system.device.getInfo()` 的 `screenWidth / screenHeight / screenShape`，反推设计高度：

```
dh      = 480 × 屏高 / 屏宽
pad     = 0                              // 贴边：留边会在胶囊屏上下露黑边
gap     = round(dh × 13%)                // 中缝，放时间用
cardH   = floor((dh - gap) / 2)          // 上半区
cardH2  = dh - gap - cardH               // 下半区（吃掉除不尽的零头）
cardW   = 480
radius  = 240                            // = 屏宽一半，与胶囊屏圆角同心
时钟大  = max(24, round(gap × 1.19))
时钟小  = max(16, round(gap × 0.766))

fontsize(n) = min(可用卡宽 / (0.60 × 位数) × 0.96, cardH × 0.74, 430)
              // 可用卡宽 = cardW − 2 × 圆角内缩(数字半高处)
列表行高  = clamp(round(dh × 12.5%), 64, 180)
```

**字号为什么要绕一层**：圆角 240 = 屏宽一半，卡片两端变成半圆，数字上下两端会被弧线吃掉宽度。
迭代 3 次收敛：`halfH = f × 0.36`、`straight = cardH/2 − 240`，
`inset = 240 − √(240² − (halfH − straight)²)`，`availW = cardW − 2 × inset`。
手环 9 上两位数比分因此从 384 降到 340。

`screenShape` 目前只用于圆屏留边（圆形屏若也贴边，四角会落在屏幕外），实际机型上报的是
`pill-shaped`（手环 9）或 `circle`（手表 S3/S4/S5）。

## 三、明确不支持

| 设备 | 原因 |
| --- | --- |
| 小米手环 7 / 7 Pro、手环 8 / 8 NFC | 平台不支持第三方快应用安装 |
| 小米手环 7 及更早 | 同上，系统是自有 RTOS 界面，非 Vela 快应用框架 |
| 手机（Android / iOS） | `deviceTypeList` 只声明 `watch`；交互也是为小屏手环设计 |

## 四、影响兼容性的 manifest 字段

| 字段 | 当前值 | 说明 |
| --- | --- | --- |
| `deviceTypeList` | `["watch"]` | 只声明手表类；手环也走 `watch`，不需要改成 `band` |
| `minPlatformVersion` | `1200` | 老机型装不上时可降到 `1100` / `1000` 再试——本项目只用到 store / brightness / vibrator / file / device / router，这些在 1000 就存在 |
| `features` | router / configuration / vibrator / brightness / storage / file / device | 少声明任何一项，对应 API 调用会被拒绝 |

## 五、扩大支持范围要做什么

1. **真机验证**（优先级）：手环 10 → 9 Pro / 10 Pro（尺寸比例差别最大）→ 手表 S4/S5（圆屏）。
   每台只需确认三点：数字不溢出、卡片四角不被裁、中缝时间不被裁。
2. **补设备参数**：在未知机型上长按记分页中缝，读出 `screenWidth × screenHeight screenShape`，
   记进本文件。
3. **放宽 `minPlatformVersion`**：确认目标机型平台版本后再降，宁可低不要高。
